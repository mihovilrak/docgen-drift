# Upgrade to lockfile schema 2

This release changes code hashing and static-member IDs. Old lockfiles are
rejected with instructions to rebaseline; they are never silently migrated.

1. Finish reviewing code and documentation changes against your previous baseline.
2. Upgrade docgen and review the configured scope.
3. Run `pnpm exec docgen baseline`, then `pnpm exec docgen check`.
4. Review and commit the resulting lockfiles with the upgrade.

Baseline accepts the current documentation state. It does not prove that the
documentation is correct. Do not edit `schemaVersion` by hand or run baseline
merely to suppress unresolved findings.

TypeScript hashes now use syntax structure, preserving regex contents,
statement boundaries, template/JSX text, and callable contract changes. Static
members use a `:static` suffix; instance IDs remain unchanged. For example,
`Store.read:static` and `Store.read` are tracked separately. Static accessors use
`Store.size:getter:static` and `Store.size:setter:static`.

Shared-lock entries record the owning project so project-scoped checks do not
report other projects as orphaned. Multi-declaration variable statements remain
visible to checks, but generation asks you to split them before editing.

The repository's existing baseline is intentionally not regenerated by this
cleanup. Review its documentation before accepting the new baseline.
